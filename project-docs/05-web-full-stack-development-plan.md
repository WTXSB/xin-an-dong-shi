## 1. 设计哲学与用户体验纲领

### 1.1 核心设计原则

```
┌─────────────────────────────────────────────────────────┐
│              心安动识 Web 设计哲学                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   🌸 柔软而非冰冷    →  圆角、柔和渐变、毛玻璃效果        │
│   🫂 陪伴而非监控    →  拟人化伙伴形象、温柔语气文案       │
│   🌿 渐进而非强制    →  低门槛入口、不评判、不催促         │
│   💡 洞察而非展示    →  数据可视化用隐喻代替冰冷数字       │
│   🧘 疗愈融入体验    →  每一次交互都是一次微型疗愈         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 1.2 用户体验"五感"设计

| 感官维度         | 设计策略                   | 具体实现                                             |
| ---------------- | -------------------------- | ---------------------------------------------------- |
| **视觉**         | 暖色调、柔和渐变、圆润形状 | 治愈绿+宁静蓝+温暖橙配色；16px圆角；毛玻璃卡片       |
| **听觉**         | 自然白噪音、柔和提示音     | 翻页声=翻书声；提醒=风铃声；完成=水滴声              |
| **触觉(移动端)** | 细腻的触觉反馈             | 按钮按下=轻微振动；滑动=惯性滚动                     |
| **情感**         | 伙伴式陪伴、正向语言       | 安小宁（虚拟伙伴）全程陪伴；所有文案用"你"而非"用户" |
| **节奏**         | 慢下来、不催促             | 页面过渡动画2-3秒；加载状态有安抚动画；无倒计时压力  |

## 3. 心安动识Web产品定位

### 3.1 与知小行的差异化

```
             知小行                        心安动识
        ┌──────────────┐           ┌──────────────────┐
        │ 大学生成长陪伴  │           │ 情绪焦虑躯体化动作  │
        │ 任务管理+习惯   │           │ 识别与心理疗愈     │
        │              │           │                  │
        │ 目标导向      │  ──VS──   │ 疗愈导向          │
        │ 行动驱动      │           │ 觉察驱动          │
        │ 效率提升      │           │ 情绪释放          │
        │ 橘猫伙伴      │           │ 安小宁伙伴        │
        └──────────────┘           └──────────────────┘

        共同基因：温暖、陪伴、不评判、游戏化、移动优先
```

### 3.2 心安动识独有模块

| 模块                | 说明                                           | 知小行有无       |
| ------------------- | ---------------------------------------------- | ---------------- |
| **🔍 视觉识别空间** | YOLO摄像头实时行为检测，温柔呈现               | ❌ 独有          |
| **💬 安心对话**     | AI智能体流式对话（DeepSeek风格），心理疗愈导向 | ❌ 独有          |
| **🌸 心灵花园**     | 行为数据→花园状态映射，焦虑减少=花朵绽放       | 庄园有类似概念   |
| **📊 情绪健康画像** | 焦虑指数、行为趋势、触发分析                   | ❌ 独有          |
| **🧘 正念练习**     | 呼吸引导+实时生物反馈+音频                     | ❌ 独有          |
| **🛍️ 安心商店**     | 品牌周边商城+星光币兑换                        | 小鱼干商店有类似 |

### 3.3 用户角色与场景

| 用户角色       | 核心场景                           | 关键页面                     |
| -------------- | ---------------------------------- | ---------------------------- |
| **焦虑自察者** | 不确定自己是否焦虑，想了解行为模式 | 首页→视觉识别→情绪画像       |
| **主动改善者** | 已知有BFRBs，希望改善              | 正念练习→CBT对话→行为追踪    |
| **陪伴需求者** | 感到孤独，需要温暖陪伴             | 安心对话→心灵花园→安小宁互动 |
| **专业用户**   | 心理咨询师查看来访者数据           | 专业面板→数据报告            |
| **周边消费者** | 认可品牌，购买周边                 | 安心商店→星光币兑换          |

### 4.2 底部导航结构（移动端）

```
┌────────┬────────┬────────┬────────┬────────┐
│  🏠    │  🔍    │  💬    │  🧘    │  👤    │
│ 首页   │ 感知   │ 安心聊 │ 正念   │ 我的   │
│ Home   │ Detect │ Chat   │ Zen    │ Me     │
└────────┴────────┴────────┴────────┴────────┘
```

**设计理由**：

- 5项导航而非知小行的8项——降低认知负荷，焦虑用户更需要简洁
- "感知"取代"检测"——语义更柔软，避免"被监测"的不适感
- "安心聊"——强调对话的疗愈属性
- "正念"独立Tab——核心功能需要一键触达

#### 6.3.2 检测中 —— "安小宁的温柔陪伴"

摄像头画面设计要素：

| 设计要素       | 实现方式                                    | 设计意图                 |
| -------------- | ------------------------------------------- | ------------------------ |
| **柔焦边框**   | CSS `backdrop-filter: blur()` + 渐变边框    | 消除摄像头的"锐利感"     |
| **暖色滤镜**   | CSS `filter: sepia(10%) brightness(105%)`   | 让画面更温暖柔和         |
| **安小宁伙伴** | 画面右下角半透明动画角色                    | 有人在陪你，不是被监视   |
| **检测提示**   | 不是弹窗，而是安小宁的"气泡对话框"          | 拟人化沟通，降低警报感   |
| **检测框**     | 圆角虚线边框 + 柔光动画，而非硬边矩形       | 温柔标记，不是"锁定目标" |
| **状态指示**   | 呼吸灯（蓝=正常，橙=检测到行为，绿=改善中） | 隐喻式状态传达           |

### 9.2 AI对话服务架构

```python
# app/api/v1/chat.py — SSE流式对话

@router.post("/chat/stream")
async def chat_stream(
    request: ChatRequest,
    current_user: User = Depends(get_current_user),
):
    """
    AI安心伙伴流式对话接口

    使用 Server-Sent Events (SSE) 返回流式响应
    前端通过 EventSource 或 fetch + ReadableStream 读取
    """

    async def generate():
        # 1. 构建对话上下文（含用户历史、今日行为数据）
        context = await build_therapy_context(current_user.id)

        # 2. 调用LLM（如DeepSeek API）进行流式生成
        async for chunk in llm_stream(context, request.message):
            yield f"data: {json.dumps({'type': 'text', 'content': chunk})}\n\n"

        # 3. 发送完成标记
        yield f"data: {json.dumps({'type': 'done'})}\n\n"

    return StreamingResponse(
        generate(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",  # Nginx禁用缓冲
        }
    )
```
